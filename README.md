# 简记 - 个人记账本系统 (Personal Ledger)

## 1. 项目简介
本项目为 2026 年 11 月 7 日现场编程作业，开发一个基于 Web 的个人记账本系统。用户可记录日常收入与支出，查看历史记录，并按日期、类别、金额等多维度查询统计，附带丰富的可视化图表展示。项目采用纯前端技术栈（HTML/CSS/原生 JS），数据持久化存储于浏览器 LocalStorage，并采用了**事件驱动架构**进行模块解耦。

## 3. 核心数据结构 (Data Contract)
所有模块的数据交互必须严格遵守以下 JSON 格式（金额必须是数字类型，禁止包含 createdAt 等额外非必需字段）：

```json
{
  "id": "record_001",
  "type": "expense",
  "amount": 25.00,
  "category": "餐饮",
  "date": "2026-11-07",
  "note": "午餐"
}
```
*(注：type 取自 LedgerConstants（income/expense）；date 必须是严格的 YYYY-MM-DD 格式且需为真实存在的日期；底层计算使用整数分以避免精度丢失)*

## 4. 架构设计与核心接口规范
系统采用**事件驱动架构（Event-Driven）**。底层数据变更后，通过派发全局事件，上层 UI 模块（列表、图表、统计）监听事件后自动刷新，实现了极低的模块耦合度。

### 4.1 数据存储与事件中心 (S7 - LedgerStorage)
- 统一操作 LocalStorage 键名 `ledger_records`。
- **事件派发**：所有增删改操作成功后，会在 `document` 上派发 `ledger:updated` 事件。S3/S4/S5/S6 无需手动调用彼此，只需监听此事件即可刷新。
- **核心接口**：`getRecords()`、`addRecord(record)`、`deleteRecord(id)`、`updateRecord(id, updates)`、`saveRecords(records)`、`seedIfEmpty()`。

### 4.2 记账表单模块 (S2 - Ledger.Form)
- **校验规则**：必填项缺失拒绝、金额为正数且最多两位小数、真实有效日期（拒绝 2026-02-31）。
- **核心接口**：`render(container)`、`init()`、`validate(fields)`、`buildRecord(fields)`。

### 4.3 财务与导入导出模块 (S4, S8)
- **财务计算**：内部统一采用**整数分（Cents）**计算，避免浮点数精度丢失。
- **导入导出**：导出 JSON 严格包含统一外壳 `{ app, version, exportedAt, records }`；导入失败不覆盖原数据，成功后自动派发 `ledger:updated` 刷新页面。

### 4.4 测试模块 (S9)
- 提供独立的 `tests/` 目录及测试用例。
- **数据保护机制**：测试前备份用户真实数据，测试结束后恢复；若测试中途报错，使用一致性验证确保数据不丢失。

## 5. 项目工程结构与运行说明
### 5.1 目录结构
- `css/`：样式表文件（响应式布局与 UI 美化）。
- `js/`：核心业务逻辑（按 S1-S8 模块严格划分）。
- `tests/`：自动化测试页面（含数据保护机制）。
- `vendor/`：第三方依赖库（如图表渲染库）。
- `index.html`：系统主页面入口。

### 5.2 运行环境与快速启动
- **环境要求**：推荐使用最新版 Chrome、Edge 或 Firefox 浏览器。
- **启动方式**：无需安装复杂依赖，直接双击打开根目录下的 `index.html` 即可运行体验完整功能。
- **测试运行**：如需运行自动化测试，请在根目录执行 `python -m http.server 8000`，并访问 `http://localhost:8000/tests/storage-test.html`。

## 6. Git 协作与质量保障
- **分支策略**：`main` (稳定版) <- `develop` (集成分支) <- `feature/SX` (个人分支)。

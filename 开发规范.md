### 2. 全局数据结构

所有模块必须使用同一条记录格式：

```
{
  id: "record_001",
  type: "expense",
  amount: 25.00,
  category: "餐饮",
  date: "2026-11-07",
  note: "午餐"
}
```

不允许私自修改字段名。

统一常量：

```
const LedgerConstants = {

```

### 4. S7：唯一数据存储入口

这是整个项目最重要的接口约定。

```
LedgerStorage.getRecords()
LedgerStorage.addRecord(record)
LedgerStorage.updateRecord(id, updatedRecord)
LedgerStorage.deleteRecord(id)
LedgerStorage.saveRecords(records)
LedgerStorage.seedIfEmpty()
```

规定：

- 所有数据必须通过 S7 读写。
- 其他模块禁止直接调用 `localStorage.setItem()` 或 `localStorage.removeItem()`。
- `getRecords()` 返回记录数组。
- `addRecord()` 返回新增记录。
- `updateRecord()` 返回更新后的记录，找不到 ID 返回 `null`。
- `deleteRecord()` 返回 `true` 或 `false`。
- `saveRecords()` 用于整体替换数据，返回是否成功。
- `seedIfEmpty()` 仅在没有数据时初始化示例数据。

### 5. S2：新增收支模块

统一命名空间：

```
Ledger.Form
```

必须提供：

```
Ledger.Form.render(container)
Ledger.Form.init()
Ledger.Form.validate(fields)
Ledger.Form.validateAmount(value)
Ledger.Form.buildRecord(fields)
```

新增记录时：

1. 获取表单内容。
2. 验证金额、类型、分类和日期。
3. 构建统一 Record 对象。
4. 调用 `LedgerStorage.addRecord(record)`。
5. 触发 `ledger:updated` 事件。

原先 S2 写的 `Ledger.Storage.addRecord()` 必须修改为 `LedgerStorage.addRecord()`。

### 6. S3：记录列表模块

```
Ledger.Records.render(container)
Ledger.Records.refresh()
Ledger.Records.deleteRecord(id)
```

规定：

- `render(container)`：首次渲染记录列表。
- `refresh()`：重新获取数据并刷新列表。
- `deleteRecord(id)`：调用 S7 删除记录。
- 删除成功后触发 `ledger:updated`。
- 记录列表不得自行保存数据。

### 7. S4：财务统计模块

保留目前已提供的 `Finance` 接口：

```
Finance.currentMonth()
Finance.calculateTotalIncome(records)
Finance.calculateTotalExpense(records)
Finance.calculateBalance(records)

Finance.calculateMonthlyIncome(records, month)
Finance.calculateMonthlyExpense(records, month)
Finance.calculateMonthlyBalance(records, month)

Finance.calculateSummary(records, month)
Finance.calculateCategoryStats(records, options)
Finance.calculateDailyTrend(records, options)
```

统一计算规则：

- 总收入 = 所有收入记录金额之和。
- 总支出 = 所有支出记录金额之和。
- 余额 = 总收入 - 总支出。
- 月度统计只统计指定月份。
- 分类统计默认统计支出。
- 每日趋势按照日期升序排列。

`calculateSummary()` 返回统一结构：

```
{
  totalIncome: 0,
  totalExpense: 0,
  balance: 0,
  monthlyIncome: 0,
  monthlyExpense: 0,
  monthlyBalance: 0
}
```

### 8. S5：筛选模块

```
Ledger.Filter.apply(records, conditions)
Ledger.Filter.reset()
Ledger.Filter.getConditions()
```

筛选条件统一为：

```
{
  type: "all",
  category: "all",
  startDate: "",
  endDate: "",
  keyword: ""
}
```

其中：

- `type`：`all`、`income`、`expense`。
- `category`：具体分类或 `all`。
- `startDate`、`endDate`：日期范围。
- `keyword`：备注关键词。

`apply()` 返回筛选后的新数组，不允许修改原始记录数组。

### 9. S6：图表模块

```
Ledger.Charts.init(container)
Ledger.Charts.update(records)
Ledger.Charts.destroy()
```

建议使用 Chart.js。

图表统一包括：

- 收入与支出对比图。
- 支出分类占比图。
- 每日收支趋势图。

图表数据必须来自 S4 统计结果，不得自己重新实现另一套财务计算逻辑。

### 10. S8：导入导出模块

保留原有接口：

```
exportToJSON()
importFromJSON(file)
```

统一 JSON 文件格式：

```
{
  "app": "personal-ledger",
  "version": "1.0",
  "exportedAt": "2026-11-07T15:00:00.000Z",
  "records": []
}
```

规定：

- 导出调用 `LedgerStorage.getRecords()`。
- 导入必须校验文件格式和每条记录。
- 导入成功调用 `LedgerStorage.saveRecords(records)`。
- 导入失败不得覆盖原数据。
- 导入成功后触发 `ledger:updated`。

### 11. S12：示例数据模块

```
Ledger.DemoData.getRecords()
Ledger.DemoData.load()
```

- `getRecords()` 返回示例数据数组。
- `load()` 调用 `LedgerStorage.seedIfEmpty()` 或按约定提供初始化数据。
- 示例数据必须符合统一 Record 格式。
- 不得在其他模块重复定义另一份示例数据。

### 13. 全局事件规范

统一事件名称：

```
ledger:updated
```

事件触发时机：

| 操作        | 是否触发 |
| --------- | ---- |
| 新增记录      | 是    |
| 修改记录      | 是    |
| 删除记录      | 是    |
| 导入数据      | 是    |
| 首次初始化示例数据 | 是    |
| 单纯筛选      | 否    |
| 单纯切换月份    | 否    |

S3、S4、S5、S6 根据需要监听此事件，刷新自己的显示内容。

### 14. 页面脚本加载顺序

统一在 `index.html` 中按以下顺序加载：

```
<script src="js/constants.js"></script>
<script src="js/storage.js"></script>
<script src="js/form.js"></script>
<script src="js/records.js"></script>
<script src="js/finance.js"></script>
<script src="js/filter.js"></script>
<script src="js/charts.js"></script>
<script src="js/export.js"></script>
<script src="js/demo-data.js"></script>
<script src="js/app.js"></script>
```

统一采用普通 script 标签，所有模块通过全局命名空间暴露接口，不混用 ES Module。

## 七、全组验收标准

所有成员提交代码前必须满足：

- 文件名与目录结构符合规范。
- 使用统一 Record 数据结构。
- 使用统一接口名称。
- 不私自操作 LocalStorage。
- 不擅自修改其他模块文件。
- 所有跨模块调用均符合接口约定。
- 没有 JavaScript 控制台报错。
- 能够完成新增、查看、删除、统计、筛选、图表、导入、导出。
- 导入错误文件不会破坏已有数据。
- 不同模块集成后能够正常运行。

特别说明： 上述 V1.0 是统一接口设计稿。S2 的 `Ledger.Form.IDS` 具体字段、S4 的统计选项对象、S6 的 Chart.js 配置等实现细节，还需要在代码接入时按本规范补充，不应由成员擅自改变公共接口。

## 八、整合期补充约定（S13，2026-11-07）

V1.0 中的规范接口全部保留，以下为联调过程中补充的**扩展约定**，各模块按此实现，不得再自行改动：

1. **图表数据口径由 S1 统一**：`Ledger.Charts` 不再自行监听 `ledger:updated`，
   由 `app.js` 在数据或月份变化后调用 `Ledger.Charts.update(records)`，
   传入“当前统计月份”的记录，保证图表与顶部概览口径一致。
2. **列表数据源可注入**：S3 提供 `Ledger.Records.setSource(fn)`，
   S1 把筛选结果注入，列表只展示筛选结果；规范接口 `render/refresh/deleteRecord` 不变。
3. **筛选栏自动挂载**：`filter.js` 检测到 `#filter-container` 后自动初始化；
   S1 通过 `Ledger.Filter.onChange(filtered, conditions)` 接收筛选结果。
   S5 在规范四条件之外扩展 `minAmount` / `maxAmount`（金额区间），
   `apply(records, conditions)` 的返回值与“不修改原数组”的约定不变。
4. **示例数据只初始化一次**：S7 新增 `allowSeedAgain()`；用户点击“清空全部账单”后，
   刷新页面不再自动写入示例数据；页面“恢复示例数据”调用 `Ledger.DemoData.restore()`。
5. **事件 action 增加 `clear`**：清空全部账单时同样派发 `ledger:updated`，
   `detail.action` 取值变为 `add | update | delete | replace | seed | clear`。
6. **交互组件统一**：S1 提供 `Ledger.App.toast(message, type)` 与
   `Ledger.App.confirm({title, message, confirmText, danger})`，
   S3、S8 不再使用 `alert/confirm`，保证提示风格一致。
7. **测试文件位置**：`tests/tests.js` 与 `tests/test-runner.html`（与第 1 节目录结构一致），
   面板内通过 `../js/...` 引用模块，直接双击即可运行。
8. **脚本加载顺序不变**：Chart.js 本地包 `vendor/chart.umd.min.js` 固定放在
   `finance.js` 之后、`charts.js` 之前。
9. **S3 账单明细改为“日历 + 当日明细”**：在规范接口之外新增
   `Ledger.Records.setMonth(month)`、`selectDate(date)`、`setOnMonthChange(fn)`；
   日历翻月通过 `setOnMonthChange` 回调 S1，由 S1 统一切换统计月份，
   保证「概览 / 图表 / 日历」三处口径一致；新增账单后 S1 调用 `selectDate()` 跳到该日期。
